# 기관 Windows에서 이어서 검증할 Codex 프롬프트

아래 내용을 기관에서 승인된 개발/시험 환경의 Codex에 전달한다.

```text
저장소 https://github.com/h19h29-design/m-edufine 의 최신 main을 읽고 기존 기능을 보존하면서 실제 K-에듀파인 호환성을 검증해라.

현재 앱은 .NET 10 WPF Windows 클라이언트 + Edge/Chrome MV3 확장 + Native Messaging/현재 사용자 Named Pipe 구조다. WebView2나 가짜 업무 DB가 아니다. 먼저 README.md, docs/RESEARCH.md, docs/FIELD-TEST.md와 tests를 읽어라.

사용자가 직접 인증서 로그인을 끝낸 승인된 시험 환경에서만 작업한다. 로그인·보안·기관 정책을 우회하지 말고 인증서/비밀번호/쿠키/HAR/민감 데이터는 수집하거나 외부 AI·GitHub로 보내지 마라. 기존 DB·브라우저 프로필을 삭제하지 마라.

1. Windows 설치/제거, 한글, 125/150% DPI, 기능키, 실제 브라우저 native messaging 왕복을 확인한다.
2. 물품관리 한 화면만 우선 읽기 전용으로 확인한다. 실제 일반 메뉴, 입력, 버튼, 그리드 구조를 관찰한다. 보지 못한 DOM 선택자/API를 추측하지 마라.
3. extension/bridge.js의 일반 DOM 방식으로 실패하는 화면은 별도 어댑터로 분리한다. 어댑터는 관찰한 구조만 사용하고 기존 제약(현재 탭/프레임, 오래된 revision 차단, 입력값 변경 차단, 민감정보 제외, 중복 저장 금지)을 지킨다.
4. 조회 조건 입력 → 실제 조회 → 원본과 앱 결과 비교를 검증한다. 승인된 시험 자료가 있을 때만 수정 → 저장 → 서버 재조회까지 한다. 결재·지급·삭제는 원본 웹 최종 처리 원칙을 유지한다.
5. 새 탭·팝업·iframe·세션 만료·탭 전환·읽기 시간초과·전용 그리드·가상 스크롤을 검사한다. 전체 행을 얻지 못했는데 전체 조회 성공으로 표시하지 마라.
6. 입력 전달, 클릭 전달, 서버 저장 확인을 별도 상태로 유지한다. 원본의 검증 가능한 성공 조건을 확보하기 전 저장 완료라고 표시하지 마라. 실패한 변경 요청을 자동 재시도하지 마라.
7. 로컬 합성 fixture와 회귀 테스트를 추가하고 Windows installer CI를 통과시킨다. 인증정보와 업무자료가 제외된 검증 결과만 문서화한다.
8. 실제 검증한 기능과 미검증 기능을 README에 갱신하고 버전을 올려 커밋/푸시/Preview Release 한다. 기존 작업을 덮어쓰거나 강제 푸시하지 마라.
```
